## PRs Merged

### myblog_worker

#### PR-7: SQS batchItemFailures + logging
- **BUG-4**: `svc.sync_album_by_spotify()` → `svc.sync_albums_batch([album_id], market)` (method didn't exist)
- **SEC-3**: Removed exception swallowing (`return True` on failure). Replaced with per-record catch → `batchItemFailures` return format
- **Reviewer catch**: initial implementation had `raise` after `failed.append()` — `raise` prevents `batchItemFailures` from being returned, causing SQS to retry the entire batch instead of only failed records
- All `print()` → `logging.getLogger(__name__)`

#### ARCH-1 fix: albums upsert ext_refs
- `ext_refs` (stores Spotify URL) was set on INSERT but missing from `ON CONFLICT DO UPDATE` — URL was never refreshed on re-sync
- Added `ext_refs = EXCLUDED.ext_refs` to the UPDATE clause

  - Old `APP_ENV` defaulted to `"dev"`, new `settings.ENV` defaults to `"local"` — local dev would hit auth guard. Fixed all `APP_ENV == "dev"` guards to `APP_ENV in ("dev", "local")`

### myblog_music

#### PR-4: Cognito JWT gate on /candidates
- Created `app/core/auth.py` — `require_cognito_token` FastAPI dependency
  - Fetches Cognito JWKS (RS256), cached per Lambda container via `lru_cache`
  - Clears cache on unknown `kid` to handle key rotation
  - Validates `token_use` claim (`access` or `id`)
  - Bypass: `ENV in ("local", "dev")` or `COGNITO_USER_POOL_ID` empty → returns `{}`
- Added `COGNITO_REGION` and `COGNITO_USER_POOL_ID` to `app/core/config.py`
- Wired `_claims = Depends(require_cognito_token)` onto `/candidates` only
- Added `python-jose[cryptography]>=3.3` to `requirements.txt`

#### PR-5: CI unit test gate
- `deploy.yml`: added `test` job (`pytest -m "not integration"`) that blocks `deploy`; deploy only on `push` to main
- `pytest.ini`: added `pythonpath = .`
- `tests/test_unit.py`: 5 unit tests for Cognito auth bypass logic (all passing)
- `tests/test_candidates_localstack.py`: added `@pytest.mark.integration` marker → excluded from CI gate

#### PR-6: tracks.spotify_id UNIQUE migration
- `db/migrations/001_tracks_spotify_id_unique.sql` — 5-step zero-downtime migration
  1. Identify duplicates (read-only)
  2. Delete duplicates, keep newest row per `spotify_id`
  3. `CREATE UNIQUE INDEX CONCURRENTLY` (no table lock)
  4. `ALTER TABLE ... ADD CONSTRAINT USING INDEX` (brief lock)
  5. Verify constraint
- Steps 3–4 must run outside a transaction block
- Worker `ON CONFLICT (spotify_id)` upserts are compatible

#### ARCH-1: schema derived header + aliases column
- Added `aliases JSONB NOT NULL DEFAULT '[]'::jsonb` to `artists` in `db/schema.sql` (was referenced in worker code but missing from DDL)
- Added "derived from docs/contracts/schema.sql" header
