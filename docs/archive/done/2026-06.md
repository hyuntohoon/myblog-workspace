## Bug Fixes

### BUG-21: `/profile` 평론 버킷 color reset to default is a no-op — ✅ 2026-06-05 (backend #53)

- `PATCH /api/buckets/{id}` with `{"color": null}` returned 200 but never cleared the color — a bucket color could be set but never reset to the default ink.
- Root cause: `bucket_service.update_bucket` guarded on `if color is not None:`, so the route's `exclude_unset` signal for an explicit clear (`color=None`) was indistinguishable from an omitted field. Fix: sentinel default (`_UNSET`) to tell "color omitted" (rename keeps color) apart from "color cleared" (`None`/`""` → default). Schema/contract unchanged.
- Found via a live prod CDP click-through of the board with a smoke JWT (color set / cover reorder / cross-bucket move / album trash→restore all passed end-to-end; only the color *reset* path was broken).
- Tests: route-contract (`color:null` forwards `color=None`) + real-engine set→clear regression. prod smoke green (`PATCH {color:null}` → 200, GET → null); smoke account `우선순위` color reset.
