### FEAT-review-bucket-board: 평론 버킷 보드 (review queue kanban + inline review drawer) — ✅ 2026-06-03

- Scope: `myblog_shared_db` + `myblog_backend` + workspace contract + `myblog_front`. Cross-repo, backend tables from the start (no localStorage MVP). All 5 steps shipped end-to-end.
- RFC: `docs/archive/done/rfcs/FEAT-review-bucket-board.md` (closed).
- **Step 1** — shared_db V6 migration + models (shared_db #13). `review_buckets` + `review_bucket_items` tables; V6 applied to Neon main (prod) + test branch **before** the PR merged (per `reference-shared-db-cross-repo-rollout`).
- **Step 2** — backend buckets API (backend #44 → infra #194). `GET/POST/PATCH/DELETE /api/buckets`, item add/update/delete, `PUT /api/buckets/reorder`; all mutations `require_cognito_token`. Single-user model — no ownership checks (buckets are global). Infra #194 added the matching API Gateway JWT routes. Recommendation signals: recency + popularity only.
- **Step 3** — workspace contract merge (#195). Merged `openapi.json` regenerated; front types derived.
- **Step 4** — frontend board UI (front #70). `/reviews/queue` kanban: user-created buckets, intra/inter-bucket drag-and-drop priority, search→add album, click→`AlbumDetailPanel`, optimistic reorder with persist.
- **Step 5** — frontend inline review drawer (front #71). `ReviewDrawer` launched from the detail panel; draft in `localStorage` per item (`bucket-draft:{id}`, isolated from the writer's `lowfreq-draft`); publish reuses `savePost` → `publishToGit`; on success item → `status=published` + `post_id` and the board moves it into the `is_done` ("작성 완료") bucket. `WriterApp` gains `?album=` prefill for "전체 편집기로 열기".
  - Decisions (2026-06-03): `is_done` bucket created on first publish + item moves there; inline draft is front-only per-item localStorage (backend has no `drafting` status flow).
  - Prod smoke: deployed-bundle grep (`qb-drawer-*`, `bucket-draft:`) + a live inline-publish e2e replicating `ReviewDrawer.onPublish()` against prod (smoke-user JWT, isolated throwaway bucket, full cleanup) — 16/16 pass: `POST /api/posts` → `POST /api/publish` (MDX committed) → bucket item `PATCH` linked → `DELETE ?hard=true` removed row + content MDX. Client-side `is_done` move not exercised against the real bucket (Step-4 reorder logic, verified by code read). See front PR #71 comment.
- Deferred (in the archived RFC, not this round): Spotify recently-played / top-tracks recommendation signal — rides the Frozen `FEAT-spotify-personalize-light` when that ships.
