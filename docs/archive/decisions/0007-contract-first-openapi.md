# ADR 0007: Contract-first workflow with strict OpenAPI enforcement

- **Date**: 2026-05-27
- **RFC**: `docs/done/rfcs/ARCH-12-contract-first-openapi.md`
- **Status**: accepted

## Context

API drift between `myblog_backend`, `myblog_music`, and `myblog_front` caused silent runtime bugs:
- Rating field: frontend `0–10` vs backend `le=5`
- `PostPayload.rating_scale` missing in frontend payload
- Music search result types maintained twice

The root cause: no authoritative, committed contract between services. Types were either hand-written or generated from a manually-exported (and possibly stale) spec.

## Decision

Adopt a contract-first workflow enforced by CI:

1. `myblog_backend` and `myblog_music` each own a committed `openapi.json` (generated by `scripts/export_openapi.py`). CI fails if a PR changes a route/model without regenerating the spec.
2. A merge tool (`tools/merge_openapi.py` in this workspace) combines both service specs into `docs/contracts/openapi.json`. Schemas are namespaced (`Backend_*`, `Music_*`) to avoid collisions.
3. When either service merges a spec update, a `repository_dispatch` triggers the workspace `merge-contract` workflow, which opens a PR updating the merged spec.
4. `myblog_front` CI regenerates TypeScript types from the merged spec and fails if the committed `src/lib/api.gen.ts` is out of date.

## Alternatives rejected

- **Per-service specs** (frontend reads `openapi-backend.json` + `openapi-music.json`): rejected because the runtime is one HTTP host; a single spec matches reality. Cross-service type references (e.g. subject type extension) are also cleaner in one spec.
- **Warn mode** (CI logs drift but allows merge): rejected because the entire point of this change is to make drift structurally impossible. Warn mode reintroduces the social-trust dependency.
- **Separate spec authoring tool** (Swagger Editor, etc.): rejected because FastAPI already generates specs from Pydantic models; introducing a separate tool adds friction with no benefit for a 1-person operation.

## Consequences

- Any route or Pydantic model change in backend/music **must** include a spec re-export in the same PR. CI enforces this.
- Frontend types are always derived from the committed spec. Type drift is a build error.
- `WORKSPACE_GITHUB_TOKEN` secret is required in all three repos (backend, music, frontend) to orchestrate the cross-repo trigger and checkout.
- Feature backlog items (rating scale fix, subject type extension, track/artist pages) are now unblocked at the contract layer.
