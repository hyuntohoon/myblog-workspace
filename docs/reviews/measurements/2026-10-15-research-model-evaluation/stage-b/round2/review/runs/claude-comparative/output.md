# Stage B 비교 보정 보고서: 17개 감사 보고서

## 1. 일관성 점검과 변경 사항

보고서 17건을 앵커 v1 §2와 R4·R5, M1·M2 기준으로 서로 대조했습니다. 같은 종류의 결함에 다른 등급이 붙은 경우는 아래 다섯 건이었고, 이것만 바꿨습니다. 게이트 혐의는 새로 열거나 철회한 것이 없습니다.

| 라벨 | 차원 | 이전 → 이후 | 결정적 근거 |
|---|---|---|---|
| S03 | D4 | BORDERLINE → **FAIL** | 보고서 원문은 "C3 발췌가 원문의 범위를 바꿨다"입니다. GRAMMY 답변은 협업 전반에 대한 것인데, 노트는 이를 Sunshine 고유 과정으로 옮겼습니다. 해당 출처는 접근할 수 있었으므로 충실도를 직접 판정할 수 있습니다. 같은 유형인 S15(발췌가 뜻을 바꿈)를 FAIL로 둔 판정과 맞췄습니다(C-D4-FAIL). D2는 M2 판정이 남아 있어 BORDERLINE을 유지합니다. |
| S17 | D4 | BORDERLINE → **PASS** | 보고서는 "발췌된 각 문장의 의미는 유지된다"고 했고, 구절도 모두 빠르게 회수됐습니다. BORDERLINE의 근거로 든 C7 '한계' 줄은 노트 자신의 주장에 있는 범위 오류입니다. 이는 D2에서 이미 감점됐으므로 D4에서 다시 셀 수 없습니다. 같은 구조인 S09는 D4 PASS였습니다. |
| S12 | D2 | PASS → **BORDERLINE** | 보고서가 직접 imprecise 1건(C5에서 "horniness"를 "욕망"으로 옮긴 것)을 세어 정밀도 18/19로 적었습니다. R4에 따르면 비중심 오류가 하나만 있어도 BORDERLINE입니다. |
| S13 | D5 | BORDERLINE → **FAIL** | 보고서 원문은 "X 게시물 문구의 모호성을 말없이 해소했다"이고, 대상은 중심 주장 C2입니다. 앵커 D5 FAIL의 "uncertainty silently resolved"에 문자 그대로 해당합니다. |
| S15 | D5 | BORDERLINE → **FAIL** | K7은 "반복 크레딧 위주"로 걸러진 Genius 집계에서 등재되지 않은 것을 "두 DB 모두 2·8·10번에만"이라고 확정했습니다. 불확실성을 말없이 해소한 것이고, 그 결과 중심 주장의 허위 상충(G4 medium)이 생겼습니다. 결과적 영향이 있는 과대 진술입니다. |

**검토했지만 바꾸지 않은 것**
- **D5 PASS/BORDERLINE 차이:** 갈린 기준은 생산자가 받은 도구 출력의 종류입니다. "Total lines"로 행 단위 원문을 받았으면 PASS(S01·S02·S03·S12·S14·S16), WebFetch 요약을 받았으면 BORDERLINE(S04·S07·S08·S11·S17)이었습니다. M1에 맞게 일관되게 적용됐습니다.
- **S11 D6 PASS vs S04 D6 BORDERLINE:** S04 제목은 "전곡 공통 프로듀서"로 사람에게 역할을 부여합니다. S11 제목 "프로듀싱 구조"는 주제 이름일 뿐입니다. 서로 다른 결함으로 보고 유지했습니다.
- **S09 D5:** C3를 미확인으로 명시했으므로 말없는 해소가 아닙니다. BORDERLINE을 유지하고, 결과적 영향이 있는지는 오너가 판단합니다.
- **S06 D4 vs S01·S02 D4:** S06만 53:42를 따옴표 직접 인용으로 제시했습니다. 결함의 종류가 달라 유지했습니다.
- **GQ 차단 건(S03·S05·S12·S14):** 감사자 쪽에서 원문에 접근하지 못한 경우는 네 보고서 모두 D4 판정 불가로 처리했습니다. 처리 자체는 일관되지만 R5와의 관계가 정의돼 있지 않습니다(§4 참조).

## 4. 다음 제한 라운드를 위한 프롬프트 변경 (5건)

1. **접근 라벨 정의 (정의).** "원문 확인"은 도구가 가공하지 않은 페이지 텍스트를 받았을 때만 붙입니다. 모델이 처리한 fetch 요약과 검색 스니펫은 "중계"로 표기합니다. 노트 첫머리에 사용한 도구의 출력 종류를 한 번 밝히고, 그에 맞춰 주장별 라벨을 적용합니다(M1을 생산자용 규칙으로 옮긴 것).
2. **상충 정의 (정의).** "상충"은 같은 역할 필드, 같은 범위(곡/앨범/판본), 같은 시점에 대한 진술끼리만 성립합니다. 잘린 스니펫이나 걸러진 집계에서 나온 부재로는 상충이나 부재를 확정할 수 없고, 이런 경우는 "범위 차이" 또는 "미확인"으로 적습니다.
3. **역할 문자열 규칙 확대 (일반화).** 원래 역할 문자열 규칙을 본문뿐 아니라 제목, 요약, 표 머리에도 적용합니다. 출처 행에 해당 문자열이 없으면 "프로듀서", "송라이팅" 같은 상위어를 쓰지 않습니다.
4. **곡별 점검표와 실행 메타데이터 줄 삭제 (삭제).** 대신 공백과 예외가 있는 곡만 번호를 나열하고, 모든 분자는 그 번호 목록에서 셉니다.
5. **인용 발췌 규칙 확대 (일반화).** 직접 발언 발췌에는 원어 구절과 그 발언이 답한 질문 또는 범위(앨범 전반/특정 곡)를 함께 남깁니다. 번역만으로 된 발췌는 허용하지 않습니다.
