## 3. 지속되는 반복 결함과 원인 해석

실제 프롬프트가 없으므로 아래 분류는 **원인 가설**입니다. 특정 규칙이나 생산 조건이 존재했다고 단정하지 않습니다.

| 반복 결함 | 관찰 사례 | 원인 해석 |
|---|---|---|
| 가공 요약을 원문 검증으로 표시 | S03·S05·S06·S07 | **혼합.** 요약을 반환하는 하네스와 그 내용을 원문 열람으로 재분류하는 모델 행동이 함께 관련된다. |
| 권위 있는 곡별 행 없이 크레딧 구성 | S01·S02·S05·S06·S07 | **모델/하네스 유발.** 접근 제한과 반환 자료의 한계가 반복되며, 모델이 대체 자료를 크레딧 근거로 사용한다. |
| 이미 받은 정보의 누락·부재 오보고 | S02·S04·S07 | **모델/하네스 유발 중 모델 측.** 보고서상 필요한 정보는 이미 제공돼 있었다. |
| 집계 범주·횟수·포함 기준 불일치 | S03·S04·S05·S07 | **모델/하네스 유발 중 모델 측.** 근거 목록과 요약 집계 사이의 내부 대조가 실패했다. |
| 비교 범위가 다른 자료의 충돌 오판 또는 성급한 해소 | S01·S03·S06 | **혼합.** 이질적인 자료 구조와 모델의 비교 판단이 함께 작용한다. S02의 독점 표현 미대조도 범위 확인 부족과 관련된다. |
| 같은 인용·한계·미해결 사항의 반복 | S03·S05·S07 | **혼합 가능성.** 문서 구성 규칙과 모델의 반복 작성 모두 후보지만, 프롬프트 유발 여부는 확인할 수 없다. |

기자 서술의 직접 인용문 조작이나 리뷰 평가의 사실 근거 전용은 반복 결함으로 확인되지 않았습니다. **프롬프트 단독 유발이라고 판정할 증거도 없습니다.**

## 4. 다음 제한된 라운드의 프롬프트 변경안

1. **출처 상태 규칙 정의:** 검색 스니펫·가공 fetch 요약·직접 검사한 비가공 원문을 구분한다. “원문 확인”은 마지막 경우의 실제 검사 범위에만 사용하며, 각 주장의 표시에 적용한다.
2. **크레딧 규칙 일반화:** 원래 역할 문자열·곡·판본·권위 있는 행을 연결한다. 미확인 상태는 표와 청취 질문에도 유지하고, 한 역할의 등재를 다른 역할 참여로 전환하지 않는다.
3. **집계 규칙 일반화:** 모든 집계에 포함 기준·분자·분모·제외·근거 행을 연결한다. 직접 발언·기자 서술·제작 과정 등의 범주를 먼저 정의하고 최종 표에서 재계산한다.
4. **불일치 판정 규칙 정의:** 역할·판본·시점·측정 단위가 같은지 확인한 뒤 충돌 여부를 판단한다. 대응 관계가 불명확하면 “미해결”로 유지하며, 부재 보고 전에는 이미 제공된 자료를 재대조한다.
5. **선택·중복 규칙 일반화:** 인용과 공통 접근 한계는 기준 위치에 한 번 제시하고 다른 절에서는 참조한다. 다만 주장별 불확실성 표시는 삭제하지 않는다.
