  - **용어 고정 (오너 매칭 2026-07-31)**: **평론 = review**(편집 권한 사용자의 장문 편집물), **평가 = rating**(사용자의 공개 별점 + 한줄평). **한국어 "리뷰"는 쓰지 않는다.** 입구는 공유하되 권한·기대치·발행 동작은 계속 분리. 지금 화면 문구가 둘을 섞어 쓰고 있어(편집 지면 빈 상태가 "아직 리뷰가 없습니다", 프로필 탭 이름 **평론**이 비편집 사용자에게는 자기 평가 목록을 보여줌, 같은 대상을 "평가"로도 부름) 화면 문구 한정으로 정리 — **URL·API·테이블 이름은 그대로 둔다** (`album_reviews`·`/api/reviews/*`는 사용자 평가인데 이름이 review라 매칭과 반대다 — 이 RFC의 파일명·plan-id도 같은 이유로 유지). **식별자 개명은 범위 실측 후 "지금 안 함"으로 결정**(2026-07-31): 내부 이름은 싸지만 **API 경로 변경이 비싸다**(openapi+프런트 타입 재생성 + API GW 라우트 3개 + apply + 구/신 병행); 파급은 backend·front·shared_db·infra로 좁다(**music·worker는 0건**). **절충 = 착수할 때 내부 이름만 정리**하고 API 경로·테이블 이름은 유지. 기회비용은 기록해 둠 — 평가 0행·클라이언트 1개인 지금이 가장 싼 시점이긴 하다.
